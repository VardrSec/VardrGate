# VardrGate v0.3.0 — controlled request boundaries

**Status: source version prepared, not published.** These notes assign changes
since 0.2.0 to version 0.3.0. They do not announce a release date, downloadable
archives or published build attestations. The module requires Go 1.25 or newer;
the build and verification workflows use Go 1.27.4.

## Changes

- Bind controlled fixed requests to reviewed case and binary hashes while
  preserving ordinary standalone CLI behavior.
- Support cooperative cancellation without background execution.
- Reject duplicate JSON keys at the fixed-request boundary.
- Protect agent-local credentials and preserve secret-scanning coverage.
- Build and verify with Go 1.27.4 to address GO-2026-6859 in the Go standard library.
- Replace retired design-document references with current user guides; separate
  public user documentation from private planning and validation notes.
- Reconcile setup, execution ownership and finding-severity exit gating with the
  implementation.

## Choose your setup path

- **Standalone Gate:** follow the [README](../../README.md) for direct CLI use.
- **Full distribution:** follow the [Full installation guide](https://github.com/VardrSec/VardrSec/blob/main/docs/installation.md).
- **Mapless distribution:** follow the [Mapless guide](https://github.com/VardrSec/VardrSec/blob/main/docs/mapless.md).

Full and Mapless use the same Gate engine at the distribution's pinned revision.
Neither requires a separate Gate HTTP queue for the integrated path. Assigning
this component version does not update distribution pins or installed binaries.

## Security and operating limits

Gate evaluates supplied cases; it does not grant permission to test a target or
infer business rules omitted from a policy. The distribution and Runner own
signed approval, credential grants and lifecycle controls. A standalone Gate
invocation does not inherit those controls merely by using this version.

Findings require human verification. Set `--fail-on` to fail on findings at or
above the selected severity; its default is `none`. Use `--fail-on-inconclusive`
when an unjudged expected outcome must also fail CI. See the
[strict-CI guide](../strict-ci.md).

Existing loopback binding, authenticated API behavior, private-target restrictions
and literal-job behavior remain in effect. Source builds must use a patched Go
compiler to receive standard-library fixes; the module's minimum Go version is
not a security recommendation.
